# DESIGN-RESEARCH.md — the reference research behind DESIGN.md

The 5 research summaries below are reproduced verbatim as they were delivered to the design judge, one section per product, each with its sources. `DESIGN.md` draws its decisions from them. The reference screenshots named in the sources live in the session scratchpad (`refs/quick.png`, `refs/hermes.jpg`, `refs/paseo.png`, `refs/cowork.png`).

## Google Antigravity

### Google Antigravity — Google's agent-first development platform. As of October 2026 it is four surfaces sharing one agent runtime: (1) Antigravity 2.0, a standalone Electron desktop app ("mission control" / Agent Manager with no code editor), current v2.19.1 (Sep 30, 2026); (2) Antigravity IDE, the original Nov-2025 VS-Code-fork editor with an agent side panel and the embedded Agent Manager window, still shipped but now the secondary surface; (3) Antigravity CLI (Go TUI, v1.2.14); (4) Antigravity SDK (Python). This report describes the desktop app (the "Manager surface") and the IDE (the "Editor surface"), plus the browser subagent that both share.

Identity: What it is: an agent-first coding product where the primary surface is a place to supervise agents rather than a place to type code. Launched Nov 18, 2025 (public preview, free) as "Antigravity IDE" with two views toggled by Cmd/Ctrl+E: the Agent Manager (an inbox of agent conversations across workspaces) and the Editor (VS Code fork). On May 19, 2026 (Google I/O) Google shipped "Antigravity 2.0": the Agent Manager became its own desktop app, the IDE was split out as a separate install ("Antigravity IDE"), Projects (multi-folder, per-project settings and permissions, Git worktrees) replaced Workspaces, and subagents, scheduled tasks, voice transcription, plugins and a CLI/SDK were added. Google's own framing: "Users interact with powerful agents both synchronously and asynchronously, and there is no IDE." Community framing: mechanically similar to Codex app (agent system extracted from the IDE), differentiated by scheduled tasks, multi-agent orchestration, the browser subagent and the artifact/verification model.

Surface described: desktop app (macOS/Windows/Linux, Electron), v2.x through v2.19.1; and the IDE (Editor view) as it existed from 1.x and continues as the separate "Antigravity IDE". Theme: dark was the default at launch; since v2.3.0 (Jul 2026) the UI theme follows system preference; onboarding offers "Dark, Light, Auto".

Models shown in the picker (not relevant to apparatus, noted for completeness): Gemini 3.x Pro/Flash, Claude Sonnet/Opus, GPT-OSS. Per-model reasoning effort Low/Medium/High (v2.5.0).

Layout: A. MANAGER SURFACE (Antigravity 2.0 desktop app)

Overall: a single window, three regions left-to-right — collapsible left sidebar, central conversation pane, togglable right "Auxiliary Pane". Plus a thin top bar, an optional embedded terminal and a toast stack bottom-right.

Left sidebar (navigation + list):
- Top-left: a "Conversation History" entry (dropdown with filters: "Only Unread" since v2.4.3; sort by "Last Prompt"; group "by project or status"; switch to "only archived conversations" since v2.18.1).
- A Projects section with a folder-plus icon ("New Project"); conversations are nested as rows under each project; the ungrouped list shows up to 30 conversations; hovering a conversation highlights the whole row and reveals row actions (pin, rename, archive); "Archive and Delete sit together at the bottom behind their own divider" in the row menu. Top-level sidebar sections collapse; collapse state is remembered. A "No Project" indicator appears when working in a scratch folder outside a project ("Conversations outside of projects … run in an isolated local scratch folder").
- A "Schedule" area for scheduled/cron tasks (`/schedule`).
- A "Documents" section (since v2.13.0) for external files (Drive links, PDFs).
- A "Customizations" tab/page (skills, rules, plugins, marketplace) with collapsible sections and item counts.
- Sidebar also hosts the embedded terminal (Ctrl/Cmd+`) and the Git "VCS review panel" since v2.10.0.
- Settings via Cmd+, or a gear; project settings via a per-project gear.
Exact pixel widths: unknown. Sidebar can be collapsed; custom pane widths are remembered.

Central pane (one conversation):
- Header: conversation title, project name next to a folder icon (hover card), a top-right control that toggles the Auxiliary Pane and shows an artifact count.
- Stream: user messages, agent prose, and "steps" — collapsible rows for terminal commands (collapsed by default while running since v2.18.1), MCP tool calls ("structured headers, expandable argument blocks, and formatted result previews"), browser steps with inline recording playback at the bottom of the step, and since v2.16.0 "Subagent cards" inline in the stream with live running/waiting/completed status, a hover Stop control and one-click navigation to the subagent's conversation in the side pane. "Turn cards" summarize each agent turn and list user-facing files; scratch files are hidden from turn cards and live in a collapsible "Scratch Files" section of the side panel. Generated images stay visible at the bottom of the turn. Timestamp shows when the response finished.
- Artifacts (plan, task list, walkthrough) appear as embedded cards in the stream with a header carrying "Proceed" and "Review" buttons; the same artifact opens full-size in the Auxiliary Pane.
- Permission requests appear inline as a dialog-like block with "a clear description of the action or command", syntax-highlighted terminal commands, approve/deny plus optional course-correction text; interactive question prompts (from `/grill-me` etc.) have option selection, a Cancel button and keyboard shortcuts, and "continue only activates once answered".
- Side questions (`/btw`) open a transient secondary thread that minimizes to a button, with back/forward controls.
- Message box at the bottom: multi-line input with "+" (attach: images, PDFs, Office, audio, .txt/.csv/.md/.json with badges), "@" (files/folders/MCP, typo-tolerant search), "/" (slash commands rendered as pills with the skill's name and logo), a model selector dropdown, a custom-agent picker (remembered after reload), a Mode choice when starting a conversation (modal: "Local mode" vs "New worktree mode"), a mic button for live transcription, and a send button. Dragging a file highlights the message box. Queued messages with a "Send Now" option. Review comments attached to the input show as "unified attachment badges" with file-grouped hover previews. Cmd/Ctrl+L focuses it; Cmd/Ctrl+N new conversation; Cmd/Ctrl+K conversation picker; Cmd/Ctrl+P file search.

Right Auxiliary Pane (toggle top-right):
- Tabs/sections for Artifacts, files (read-only file viewer with breadcrumbs and preview tabs that are temporary until promoted), "Review Changes" diffs (side-by-side, "Hide Whitespace Changes", image diffs for PNG/SVG), subagent conversations, an "overview pane" showing nested subagents, and an in-app URL preview pane ("Sidecar" links render as pills that open here). Code/data artifacts open in a virtualized syntax-highlighted viewer. Width is user-resizable and remembered. "Conversation Width" (max width of the thread) is a setting under Appearance.

Multiple agents / threads: shown as the conversation list in the sidebar (one row per conversation, grouped by project or status), plus subagent cards inside a parent conversation and a `/agents` live checklist (identifier, role, state, current step). There is no kanban board in the shipped product; one third-party guide describes a "Kanban-shaped board" but no official source or screenshot corroborates it — treat as unverified. The 1.x "Inbox" (a middle column listing every conversation across workspaces like email, with Idle/Running/Blocked status) is, in 2.0, folded into the sidebar conversation list plus the "Only Unread" filter and OS/toast notifications; a separate inbox pane is not documented for 2.x.

Other chrome: command palette (Cmd/Ctrl+Shift+P) over a dimmed backdrop with enter/exit animation and wrap-around arrow navigation; toasts bottom-right collapsing into a compact stack (8 s); a loading screen with a pulsing Antigravity logo; tray icon on Windows/Linux; "Remote Control" lets any browser attach to a session.

B. EDITOR SURFACE (Antigravity IDE, 1.x lineage)

VS Code layout: activity bar + file explorer left (Cmd/Ctrl+B), editor tabs center, terminal bottom (Ctrl+`), and the Agent side panel on the right (Cmd/Ctrl+L to focus, Cmd/Ctrl+Shift+L new thread). The Agent panel: conversation stream at top; a bottom toolbar above the input that tracks "open file changes, running terminal processes, and artifacts" and holds the "Review Changes" button; the input has a Planning/Fast mode toggle (checklist icon = Planning, lightning icon = Fast), model picker, image attach, @ mentions. Inline command Cmd/Ctrl+I in editor or terminal; tab completions. A small icon top-right (and Cmd/Ctrl+E) switches to the Agent Manager window. "Review Changes" opens an editor pane that scrolls through all diffs made in the conversation; each diff can receive a comment addressed to the agent.

1.x Agent Manager (inside the IDE, still what most screenshots online show): three columns — left: Workspaces list plus a "Playground" sandbox; middle: the Inbox (each conversation a row with a title and a status of Idle / Running / Blocked); right: the selected conversation with its artifacts. Left nav labels seen: "Start Conversation", "Workspaces", "Playground", "Browser", "Editor View".

C. BROWSER (shared)
A real Chrome instance driven by the browser subagent (opt-in via `/browser`). While the agent controls it, the Chrome window shows a blue "Agent Control" border and a red dot as the AI cursor. Screenshots and video recordings are captured; recordings play inline at the bottom of the browser step and are saved as "recording artifacts" that loop through the subagent's actions.

Signature: 1. Artifact cards with Proceed/Review headers. Implementation Plan, Task List and Walkthrough render as document-like cards inside the thread (and full-size in the Auxiliary Pane). The plan card header has "Proceed" and "Review" buttons; the agent pauses for review unless the "Artifact Review Policy" is "Always proceed". The walkthrough embeds screenshots and recordings inline and can be exported as PDF from an overflow menu.

2. Google-Docs-style comments on everything. You select text in a plan, a diff, or drag a rectangle on a screenshot/image, and leave a comment; comments collect as badges on the input ("attached review comments"), and a hover on a file's comment-count pill previews all comments. Draft comments persist. This is the product's defining interaction.

3. The task list as a live checklist. The agent "writes its plan as it works, ticking off steps and noting where it backtracked"; shown as a checklist artifact that updates during the run.

4. Step rows. Terminal commands, tool calls, file edits and browser actions are compact collapsible rows in the thread: command text syntax highlighted, a shield badge when run in the sandbox, collapsed while running, and a status word (CLI wording: Running / Errored→"Failed" for non-zero exit). MCP calls get a structured header with expandable args and result preview.

5. Subagent cards. Dedicated cards in the stream with a live status (running / waiting / completed), a hover Stop, and a link that opens the child conversation in the side pane; nested subagents are visible in an overview pane; `@subagent` in the message box messages one directly.

6. Review Changes diff pane. Side-by-side diffs grouped by file with per-file comment pills, "Hide Whitespace Changes", image/SVG side-by-side previews, and a Git VCS panel for working-tree diffs and commits.

7. Browser recordings and the "Agent Control" border. Looping video artifacts of what the agent clicked, plus the blue window border and red cursor dot in Chrome during automation — the most "demo-able" element.

8. The composer. A tall rounded message box with "+" / "@" / "/" affordances, slash commands rendered as pills with skill logos, a model picker, agent picker, mic, send; a Mode modal (Local vs New worktree) when a conversation starts; queued messages with "Send Now".

9. Permission prompts and question panels. Inline blocks that stop the run: a described action, highlighted command, approve/reject with optional correction; question panels with option selection and Cancel.

10. Keyboard model. Cmd/Ctrl+E (Manager ↔ Editor), Cmd/Ctrl+L (focus input / quote selection), Cmd/Ctrl+I (inline command), Cmd/Ctrl+N (new conversation), Cmd/Ctrl+K (conversation picker), Cmd/Ctrl+P (file search), Cmd/Ctrl+Shift+P (command palette, which can pin/rename/archive conversations and toggle light/dark), Opt+Cmd+P pin, Cmd+\ terminal split, Ctrl+M dictation, Alt+J jump to subagent awaiting approval, Cmd+F find in conversation, PgUp/PgDn/Home/End scroll the thread.

Visual: Overall register: a quiet, spare Google-product look — flat surfaces, hairline dividers, small type, little decoration; density is closer to an IDE than to Claude/Quick. Screenshots in the wild are overwhelmingly dark-mode.

Palette (dark): the app ships theme presets borrowed from the editor world. The reference dark preset is "Vesper" (Rauno Freiberg), whose source values are: background #101010 (editor, sidebar, title bar, status bar), active tab #161616, input #1C1C1C, list selection #232323, foreground #FFFFFF, line numbers / muted #505050, keywords #A0A0A0, comments #8B8B8B at ~58%, accent #FFC799 (peach; used for focus ring, buttons, badges, links, warnings), with #99FFE4 mint as the secondary code accent. Antigravity's own Vesper variant was "updated with lilac and pink accents for keywords and operators, and dimmer comments" (v2.14.0), so expect a near-black UI with a soft lilac/pink/peach accent family rather than Google blue. "Darcula" preset also exists (JetBrains palette: #2B2B2B bg, #A9B7C6 text). The exact default UI chrome colors of the 2.0 app outside these presets: unknown. Light theme values: unknown (the app ships one; no token source found). Marketing site tokens (not the app): primary #121317 on white, pill buttons in near-black.

Typography: the website uses Google Sans / Google Sans Flex (32px medium headlines, 16px body). The app's UI family is not documented; it is an Electron app descended from VS Code so expect the system UI stack (SF Pro / Segoe UI) with a monospace for code. Sizes are small: users on the Google forum describe the agent sidebar text as "really, really small" with no setting to enlarge it; v2.15.0 lightened chat bold weight. Diff and code use a mono face; KaTeX, Mermaid, Chart.js/Plotly render inline.

Shape and surfaces: flat panels separated by 1px borders rather than shadows; cards (artifacts, subagent cards, turn cards, permission blocks) are low-contrast filled rectangles with modest radii (looks like 6–8px; exact value unknown). Pills are used for slash commands, sidecar links, comment counts, attachment badges. Status badges: shield (sandbox), "No Project" chip, archive folder icons.

Density: high. Conversation width is user-capped ("Conversation Width" setting); step rows are single-line and collapsed by default; the sidebar lists up to 30 ungrouped conversations.

Iconography: thin line icons; refreshed Google Docs/Sheets/Slides/Drive glyphs for document attachments; folder icon next to project names; terminal glyph on command steps; checklist icon = Planning mode, lightning = Fast mode (IDE).

Motion: restrained — command palette has enter/exit animation over a dimmed backdrop; toasts slide into a bottom-right stack; a pulsing Antigravity logo on the loading screen; subagent cards animate their live status. The 1.x IDE had an ambient glow around the UI while the agent "thinks", which a reviewer reported caused input lag; whether 2.0 kept it: unknown.

Agent state: Per conversation (sidebar list / 1.x Inbox): three states — "Idle" (waiting for nothing / finished), "Running" (actively processing), "Blocked" ("the AI needs your input before it can continue"). 2.x adds unread state (an "Only Unread" filter) and sorting/grouping "by status". Exact glyphs/colors of the sidebar status indicator: unknown (not documented; community reports describe them as small status icons).

Inside the thread:
- Running: a loading indicator under the last turn that "shows what the agent is doing while it prepares a response"; terminal steps show a Running state collapsed; subagent cards show "running"; the status bar / `/agents` checklist shows state and current step.
- Waiting / needs input: a permission request block (action description + highlighted command + approve/deny with optional course correction), a question panel (options, Cancel, continue disabled until answered), or an artifact header waiting on "Proceed"/"Review". Subagent cards show "waiting"; the status bar posts "subagent needs approval" and Alt+J jumps to it. OS notifications ("xyz AG task completed") and toasts (bottom-right, 8 s) announce transitions when you are elsewhere; the 1.x IDE showed "a notification in the corner of the editor" with a click-through to the artifacts.
- Done: the Walkthrough artifact appears automatically when implementation completes; the turn gets a finished timestamp; subagent card "completed"; task-list items ticked.
- Error: CLI step titles changed from "Errored" to "Failed" for non-zero exits; hook config errors are rejected at load with a clear error; a generic "Something went wrong" screen appears on crashes (forum reports). Background tasks are shown as running / paused / completed. Quota exhaustion is a dedicated screen (used vs remaining credits).

Browser automation state is communicated outside the app: a blue "Agent Control" border on the Chrome window and a red cursor dot.

Voice: Input only. Antigravity 2.0 added "built-in live voice transcription": a mic icon beside the message box; click to start, click again (or Ctrl+M) to stop; words stream into the input field in real time (Gemini Audio model, "smart cleanup" of pauses and fillers); you can press send while dictation is still running (v2.12.0). Available on all tiers. It is dictation into the composer, not a voice conversation: there is no spoken output, no orb, no voice model, and no push-to-talk vs open-mic distinction. The CLI has `/voice` and F5. Audio files can be attached (mp3/wav/m4a/aac/ogg/flac/opus up to 20 MB) and audio plays inline. Reviewers note proper nouns and version numbers mis-transcribe. The recording-state visual (waveform or color change): unknown.

Critique: What works (with evidence):
- The artifact-not-logs model is the product's real idea and reviewers consistently praise it: "verify with Artifacts, not logs"; a task list "ticking off steps", screenshots as a film strip, recordings that loop. For apparatus this maps directly onto the voice composer's job cards: show outcomes (plan, checklist, screenshot/recording), not tool noise.
- Comments-on-anything (text, diff lines, image regions) is the best feedback loop in the category; it lets the user redirect without stopping the run.
- The sidebar/thread/aux-pane triad with step rows collapsed by default keeps a long agent run readable; v2.16's subagent cards (status + stop + open) are a clean pattern for parallel work.
- Thorough keyboard model and command-palette coverage (pin, archive, rename, theme toggle).
- Honest state words: Idle / Running / Blocked are plain and glanceable; Blocked is the right framing for "needs input".

What does not work (with evidence):
- Stability and trust. The May 2026 auto-update replaced the IDE with the agent app mid-session ("I no longer have access to the IDE"), users lost the file explorer, chats and themes, and the fix was renaming app.asar. Forum threads report Agent Manager freezes every few operations ("Something went wrong"), orchestrator hangs every 4–5 hours, and conversations disappearing from the sidebar. A 1.x reviewer: buttons stop working, sidebar icons vanish, "Review Changes" instantly closes, and the thinking glow causes input lag.
- Type is too small and not adjustable in the agent panel (Google acknowledged there is no setting); on 4K/5K displays it is "extremely small". For apparatus: 13–15px UI type and a real size control.
- The IDE-derived chrome is dense and flat; the 2.0 app reads as a developer tool, not the calm "quiet card" surfaces of Quick or Cowork. It lacks a greeting/empty state and uses editor theme presets (Vesper, Darcula) as its visual identity instead of a product palette; light mode is an afterthought (dark was default until July 2026).
- No inbox in 2.0: the cross-project triage view of 1.x became a filtered sidebar list plus OS notifications; "needs input" items are not surfaced as a first-class queue with inline actions the way Cowork's "Needs input 2 / Ready for review 7" chips and "Approve once" buttons do.
- Voice is dictation only; no spoken output, no hands-free mode.
- Security: 1.x rendered images from arbitrary URLs in the chat, enabling prompt-injection exfiltration (BetterStack); treat anything that renders remote content in the thread as a risk.
- Documentation of the visual system is thin: no published tokens for the app, so radii, exact chrome colors and the light palette remain unknown; several third-party guides invent details (e.g., a kanban board) that no official source shows.

How it sits against the four references (viewed): Quick is the lightest and most "product" of the set (white, one purple, 240px sidebar, activity card of tool rows, big composer card); Hermes is the most atmospheric (glassy dark panels on a wallpaper, agents list with status dots, pill composer with an orb, slim status bar); Paseo/Codex is the most engineering-dense (diff stats in the sidebar, Changes|Files pane, tool calls as one-liners); Cowork is the warmest and best at task triage (filter chips with counts, status glyphs, inline action buttons). Antigravity sits between Paseo and Hermes in density and darkness, and beats all four on artifact/verification presentation and on commenting, but trails all four on calm, type size, light mode and stability. For apparatus: keep Antigravity's artifact cards, step rows and Blocked/Running/Idle honesty; take the sidebar+recents+settings skeleton and 13–15px type from Quick; the status-dotted agents list, orb-in-composer and slim status bar from Hermes; the diff/changes side pane from Paseo; the needs-input chips and inline Approve/Respond actions from Cowork.

## Amazon Quick

### Amazon Quick (formerly "Amazon Quick Suite"). Quick Suite launched 9 Oct 2025 as the evolution of QuickSight + Q Business (Quick Index, Quick Research, Quick Sight, Quick Flows, Quick Automate, Spaces). AWS shortened the name to "Amazon Quick" in 2026 (docs moved from /quicksuite/ to /quick/; Q Business and Kendra went into maintenance for new customers after 30 Jul 2026). "AWS Quick" in the user's request = this product; there is no other 2026 product by that name. The surface described here is the Amazon Quick DESKTOP app (macOS/Windows, Electron-style; preview 28 Apr 2026, GA 9–10 Sep 2026), because that is what the author's reference screenshot shows and it is the only surface with the chat-centric "agentic teammate" UI (feed, Mission Control, background routines, voice). The web experience (Flows, Automate, Research, Spaces builders) is described where the desktop defers to it. Pricing for context: Free $0, Plus $20, Max $100 /user/mo; Enterprise Professional $20 + $250/mo infra, Enterprise $40 + $250.

Identity: Identity: an enterprise work assistant that lives on the laptop, indexes local folders, connects to Slack/Outlook/Gmail/Teams/Calendar/Jira/Salesforce etc., builds a personal knowledge graph, and runs agents on cloud "routines" that keep going while the laptop is closed, posting results to an activity feed. Positioning words from AWS: "your agentic teammate", "learns how you work", "local-first" (desktop keeps folder permissions/creds locally; conversations, memory, graph and index live in the AWS account and sync across web, mobile, desktop). The feel: a quiet, white, document-like enterprise chat (closer to ChatGPT-desktop/Claude-desktop than to a BI console), with one purple accent carried by the product mark, the stop button and the avatar, and with agent work expressed as terse "activity" rows rather than big cards. Release described: desktop GA build (Sep 2026) per docs dated Oct 2026; the author's screenshot is the aboutamazon hero image, which matches the GA sidebar (New chat / Feed / My stuff / More, Recents, Settings group with Capabilities / My computer / My context / Customization). Note the docs now describe a slightly newer rail ("Chat, Feed, Library, Customize, Apps, Spaces, More" + "Edit navigation"), so two generations of labels coexist in late 2026; a designer should treat the screenshot as the visual reference and the docs as the feature inventory.

Layout: MAIN SCREEN (desktop, measured from the author's screenshot, app window ~1110 px wide at screenshot scale): four regions — (1) LEFT SIDEBAR ~22% of window width (~244 px at this scale; roughly 240–300 px real), flat #f9f9fb, separated from the main area by a 1 px #f1f1f3 divider, no shadow. Top row: product mark (hexagonal purple/pink "Q" glyph) + "Amazon Quick" in medium weight + a collapse-panel icon at far right. Primary nav as full-width rows (row height ≈ 20 px at screenshot scale; ~28–32 px real) with thin 1.5 px line icons left and 13 px labels: "New chat" (selected: lavender #e8e6ff pill, 6 px radius, no border, icon/label stay dark gray), "Feed", "My stuff", "More ›" (chevron right; opens Apps, Chat agents, Research, Flows, Spaces, Dashboards — i.e. the web surfaces). Then a "Recents" section header in muted gray with three 14 px icons (filter, folder, search) right-aligned; conversations listed by date and in folders with counts; per-item menu offers pin, rename, move, archive, delete; "Auto-clean up" sorts chats into topic folders. Pushed to the bottom: a thin divider, a collapsible "Settings ^" group listing "Capabilities" (Connections / Skills / Scheduled Tasks / MCP / System tabs), "My computer" (Local Folders, Search Indexing), "My context" (Knowledge Graph, Memory), "Customization" (Activity Feed, Appearance, Notifications, Browser, Screenshot, Voice, Performance, Message Keybinding, Local Processing, Troubleshooting, Danger Zone); then a 22 px solid purple (#7300e5) initials avatar + user name. Docs version: profile at the bottom opens an account menu (My context, Settings, Help, Sign out, session-usage meter). (2) TOP BAR: window chrome with back/forward arrows at left; at top-right four small icon buttons (activity-monitor pulse, Mission Control, Tasks/Agents, All data & apps) plus a "Preview" badge in preview builds and a connection-status indicator; Mission Control opens as a popover (agent runs, pending inputs, routines, "View all"). An "Incognito" control sits at the top right of the chat surface. (3) MAIN THREAD on #fcfbfd, single column with ~60 px side gutters, max ~740 px content at screenshot scale: user message = right-aligned bubble, fill #f3f3f7, ~8 px radius, 12 px vertical padding, no border; assistant turn = header row [small logo + "Quick" bold + tiny agent chevron] — thin rule (#edecf0) stretching to the right — right-aligned meta in 11 px gray "Loaded 1 skill, used 1 tool"; below it the activity card (see signature elements), a hairline, then plain prose with no bubble. Home state (no thread) shows a time-aware greeting, the composer, connection-setup cards for unconnected sources, and a "Quick Briefs" condensed feed. (4) COMPOSER pinned at bottom (see signature elements). Critique: WORKS: (1) The activity card is the best idea here — tool work reads as a short, calm checklist inside a gray slab, so a six-step agent turn costs ~130 px, not six cards; the summary line "Loaded 1 skill, used 1 tool" gives accountability without noise. (2) Restraint: one accent, flat tonal surfaces, one elevated object (the composer) — the eye goes straight to where you type. (3) The feed model ("burns down", importance levels, auto-resolve, briefing three times a day, catch-up on return) and Mission Control (KPI tiles, unblock filter, run list) are a genuinely good answer to "where did my agents get to"; the AFK recap is a small, smart touch. (4) Scoped Spaces ("if the answer is not in the space, Quick tells you so") and Incognito make trust boundaries visible in the UI. (5) Response mode + thinking effort as a single composer picker with /mode as a keyboard equivalent is tidy. DOES NOT WORK: (1) Two sets of labels in the wild (screenshot: New chat / Feed / My stuff / More + Settings group; docs: Chat / Feed / Library / Customize / Apps / Spaces / More + account menu) — the product is still being renamed under users, and "More ›" hides the web-only builders (Flows, Research, Automate, Spaces on older builds), so the desktop app is a front door with the workshops in another building; the my2cents hands-on review explicitly flagged "Research, Chat Agents, Flows, and Spaces are not in the desktop app yet". (2) Settings scattered across three places (sidebar "Settings" group with 4 pages × many tabs, account-menu Settings with 5 tabs, and Customize) — the Customization page alone has 11 subsections. (3) State is told, not shown: no color-coded status glyphs in the thread or Recents, so a blocked background task is invisible unless you open the Tasks panel, the agent page or Mission Control (compare Cowork's status glyph per task). (4) The composer's two square buttons (outlined plan icon, filled stop) are unlabeled and visually identical in size; the tiny "Quick ⌄" agent switcher in the top-left of the composer is easy to miss. (5) Enterprise friction: $250/mo infra fee on Professional, agent-hour overages, macOS preview Gatekeeper warning, feature gaps vs web, vendor lock-in (cloudvisor, my2cents). (6) Dark mode exists but is undocumented visually anywhere public — a designer cannot copy it. (7) Voice: dictation/Talkback is bolted on (orange mic as the only state cue, Windows focus bug). FOR APPARATUS: adopt the activity card + header meta line, the lavender selected-row pill, the single elevated composer, the flat tonal sidebar, 13 px UI type and the feed/Mission-Control idea of a "needs input" filter; do NOT adopt the buried More › menu, the three-way settings split, or text-only state — give each job row a status glyph as Cowork does, and keep the composer's buttons labeled (Talk / Stop) since the orb is the state indicator.

Critique: WORKS: (1) The glass-over-wallpaper look with opaque text surfaces is distinctive and legible; the Frost/Intensity/Area controls let users dial it back. (2) The status bar is an honest telemetry strip (gateway, agents, cron, tokens, cost, model, context %) and is customizable and hideable; community plugins (hermes-session-monitor, hermes-token-cost, ledgerline) extend it, proving the slot works. (3) Tool activity as compact collapsible rows with a separate technical view is the right default; artifacts "offer, don't hijack" (open on click) is good restraint. (4) Keyboard model is thorough: Cmd+K palette that covers navigation, settings, theme and color mode; rebindable shortcuts; tab-style session cycling. (5) Theming is unusually deep: one YAML skin themes CLI, TUI, desktop and dashboard, VS Code Marketplace themes import, OKLCH utilities and a 4.5:1 contrast floor; community packs of 100+ themes exist. (6) Voice is integrated into the composer rather than a separate mode screen. DOES NOT WORK: (1) Feature sprawl: nine-plus sidebar sections, titlebar clusters, status groups, Kanban, Bots, Projects, HUD, group rooms; Nous had to add a Simple mode (PR #118587) and a community repo (desigrit/hermes-config) exists specifically to "suppress some of the visual chaos", hiding titlebar buttons and restyling bubbles and the input. (2) Message hierarchy is weak: issue #93915 says user and assistant turns "appear with similar styling, making the conversation flow difficult to scan"; the fix was more skin tokens, not a stronger default. (3) Chrome churn: v0.21.1 silently moved Settings/HUD/layout from the right titlebar to the left and dropped the haptics toggle (issue #107351). (4) Persistence gaps: zoom level not remembered across launches was called "the worst experience" (issue #50760, since addressed). (5) Stability of the Electron shell: startup crashes on Windows (issues #38216, #51713), silent launcher failure on Linux without setuid chrome-sandbox (#51327), build failures (#37544), and a "keeps crashing" circuit breaker, which says a lot. (6) Monospace-leaning default typography (Courier Prime + JetBrains Mono in the `nous` preset) reads as a developer tool, not a consumer assistant; the GitHub-Primer palette makes the default light theme look like a GitHub page. (7) ~109 skills active by default inflate per-prompt cost; the UI does not surface this well. (8) Linux still requires a terminal install, undercutting "goodbye command line". (9) The reference screenshot shows the early beta, not the current build: the current sidebar is SESSIONS | BOTS with more rows, so copying the screenshot literally would reproduce a layout Nous has already moved past. For apparatus: take the status-bar sentence, the compact tool rows, the pinned/agents groups with status dots, the mic-centered composer and the quiet glass surfaces; skip the sprawl, the mono display face and the GitHub palette.

## OpenAI Codex Desktop and Paseo

### OpenAI Codex Desktop (the Codex surface of the unified ChatGPT desktop app, macOS, Oct 2026) and Paseo (open-source multi-provider agent client, desktop + mobile, v0.10.x / 0.11 beta, Oct 2026)

Identity: CODEX DESKTOP. What it is: OpenAI's native desktop "command center for agents". Launched as the standalone Codex app for macOS (Apple Silicon) on 2 Feb 2026, Windows on 4 Mar 2026. On 9 Jul 2026 the Codex app merged into the unified ChatGPT desktop app: the binary renamed itself to ChatGPT.app and the shell now exposes three modes, Chat, Work and Codex; "Codex keeps its dedicated view and separate history" (changelog, Jul 13-17). Docs moved from developers.openai.com/codex to learn.chatgpt.com. So "Codex Desktop as of October 2026" = the Codex view inside ChatGPT.app, builds 26.9xx (e.g. 26.901, 26.924, 26.928, 26.930). Surface described here: macOS desktop, dark theme default appearance (Light/Dark/System available). Closed source (the CLI is open); every UI fact below comes from official docs, the dated changelog, GitHub issues filed with screenshots, or hands-on reviews. Model: GPT-5.3-Codex at launch, later GPT-5.x models; reasoning effort low/medium/high/xhigh (plus "max"/"ultra" on some models). Running modes: local (your folder), worktree (isolated git worktree per thread), cloud ("Work in > Cloud" environments). PASEO (paseo.sh, github.com/getpaseo/paseo). What it is: a self-hosted "control plane for coding agents" by a solo maintainer (Mo Boudra). A local TypeScript daemon runs first-party agent CLIs (Claude Code, Codex, Copilot, OpenCode, Pi, Cursor, Antigravity, Muse Code, 30+ via ACP); clients are an Electron desktop app, Expo/React Native iOS/Android apps, a web UI and a CLI, all sharing one React Native codebase (react-native-unistyles for theming). Apache-2.0, ~19.5k GitHub stars, no telemetry, no account. Surface described here: desktop app (the author's screenshot is the official paseo.sh hero mockup) plus the phone client. Done / unread: "A blue dot notification appears when a task completes"; the blue unread dot persists until the thread is opened; Shift+Escape clears all unreads; the command menu has an "Unread chats" section; the Activity view lists "work that needs your attention"; the Windows taskbar/Dock shows an unread badge; turn-completion notifications are configurable. Automations: rows show next run time and status; outputs appear in Triage with Approve / Revise / Reject. PASEO. A single derived bucket per agent/workspace (protocol agent-state-bucket.ts): needs_input (pending permissions or attentionReason "permission") > failed (status error) > running > attention (finished and requiresAttention) > done. Sidebar dot colours: needs_input = statusDotWarning (amber, "because it wants something from you"), failed = statusDotDanger (red), running = statusDotRunning (blue, "the one busy state that asks for nothing"), attention = statusDotSuccess (green), done = no dot (or border-grey when "show done as inactive"). Voice: CODEX DESKTOP: dictation (Ctrl+Shift+D) with a "dictation dictionary" and cleanup (May 2026); "voice chat" / realtime voice mode (Ctrl+Shift+V) that can delegate to Codex with a tooltip explaining it uses thread context, plus "Screen context" (an appshot of the frontmost window) in voice mode (Jul 2026). Critique: CODEX DESKTOP, what works: the project > thread > worktree > review-queue model is the clearest expression of "many agents, one inbox"; the review pane (scope chips, per-hunk stage/revert, hover-plus comments that go back to the agent) is the strongest diff UX in this category; the dense, searchable, fully remappable shortcut table and Cmd+K/Cmd+P/Cmd+G make it keyboard-first; theming is deep (accent/surface/ink/contrast/opacity/fonts/diff colours, shareable theme strings); Quick Chat / mini windows let you keep a thread beside other work; computer use with its own cursor in the background is unique on macOS. What does not: state signalling is fragile and under-designed: the running spinner sits at the far right of crowded rows and "is easy to miss" (#49984), the blue unread dot silently regressed in 26.930 (#50856), threads get stuck "thinking" (#34026) and the sidebar spinner never stops (#46801, #13740); the "Last turn" review header can show the wrong turn's diff, a data-integrity bug (#40830); dark-mode selection contrast in the composer is near-illegible (#42491); Appearance colours do not reach the sidebar, so Codex and ChatGPT windows are indistinguishable in dark mode (#21841); the July merger made the shell three products in one and users must set "Codex as the default opening view" to avoid landing in Chat; reviewers note the CLI's compact status line "doesn't exist in the desktop app" and worktree UX is "awkward"; model picking is unavailable for cloud chats; the model picker lists each model once per reasoning effort in some integrations. Feature sprawl (Pets, image canvas, Sites, Canva, plugins marketplace) dilutes the agent command-center focus. PASEO, what works: the design doc is the most disciplined of the four references ("A row, a label, a control"; one accent CTA per page; borders not shadows; weight-and-colour hierarchy at one 14px base; OKLCH-normalized status families with documented contrast floors; sentence-case copy rules), and the shipped UI matches it; the sidebar row packs state, diff stat and PR meta into two lines without noise; tool calls as one-line rows keep the timeline scannable; the composer's pickers are exactly the three that matter (model, thinking, mode) plus mic and voice; true mobile parity and local voice are real differentiators; everything is open so tokens can be copied verbatim. What does not: HN reviewers called the look "basic tailwind" and questioned "beautiful"; the dark default is a slightly muddy teal-grey (#181B1A) with a low-chroma green accent (#20744A) that barely reads as an accent; the hero shows a thin 1px border around the composer with no elevation, so the composer does not pull focus the way Quick's or Cowork's do; tool rows have no success/failure marker inline (you only learn from the prose); reasoning display was cluttered enough that a community fork ("Paseo Smooth UI") exists for "inline reasoning, compact tool activity, Markdown that reads like Markdown"; App Store reviews ask for session persistence when the app is backgrounded; large diffs stalled until 0.7.2; the tab strip truncates titles aggressively; the app is a single-maintainer project with fast-moving settings structure (reorganised again in 0.10.0).

## Claude Desktop (Chat, Cowork, Code)

### Claude Desktop (Anthropic) — the native macOS/Windows (Linux beta) app that bundles three top-center tabs: Chat, Cowork and Code, plus the claude.ai web surface it mirrors. Described as of October 2026, after the 16 Sep 2026 merge of Chat and Cowork into one composer (rolling out to Pro/Max first) and the 14 Apr 2026 Claude Code Desktop redesign (Mission-Control sidebar, drag-and-drop panes).

Identity: What it is: Anthropic's first-party client for Claude. One Electron-style window, no browser chrome, with a three-way tab switch at the top center of the title bar ("Chat | Cowork | Code"). Chat = claude.ai conversations, projects, artifacts, connectors/MCP. Cowork (research preview Jan 12 2026, Dispatch added Mar 2026) = the agentic surface for non-coders: pick a folder, Claude plans, executes with tools, asks for permissions, delivers files. Code = Claude Code with a GUI: sessions, diff review, terminal, browser pane, PR monitoring.

Which surface this report describes: primarily the desktop app (v1.2581.0+ for panes; v1.46388.1+ for view modes), with the web (claude.ai) and mobile Cowork views as shown in the author's reference image (cowork.png, the Sep 2026 "Cowork expands to mobile and web" press image). Note the state is transitional: the press image still shows a segmented "Chat | Cowork" toggle inside the composer, while TechCrunch/Yahoo report that the separate Cowork toggle is being removed and Claude now routes requests itself, with an "Output" button exposing Docs, Slides, Design and Artifacts. Both states exist in the wild in October 2026.

Feel in one sentence: a warm, paper-like, editorial reading surface (ivory canvas, serif display greeting, one terracotta accent) wrapped around a tool that quietly lists what it is doing in muted gray rows and interrupts you only with small bordered permission cards.

Critique: WHAT WORKS (evidence)
- The warm palette plus serif greeting makes it the most recognizable agent app at a glance; community DESIGN.md reconstructions (VoltAgent, shadcn, designmd) all converge on the same four tokens (#faf9f5, #141413, #d97757, #b0aea5), proof that the system is coherent enough to be reverse-engineered.
- Tool activity as single gray rows in one quiet card keeps the thread readable; the Normal/Thinking/Verbose switch (Ctrl+O) gives power users detail without burdening the default.
- Permission UX is consistent across surfaces: "Allow once / Always allow / Deny" on sites, "Allow for this session / Deny" on apps, and the mobile "Approve once" card means a phone can unblock a desktop task (Dispatch push notifications).
- The Code tab's pane model (diff with line comments and "Review code", browser pane, terminal, tasks pane, side chat via "/btw") is deeper than Codex/Paseo's two-pane layout, and the sidebar filters (status/project/environment) handle many parallel sessions.
WHAT DOES NOT (evidence)
- Mode confusion: Anthropic itself admitted "customers often struggled to choose the right tab for the right task" and removed the Chat/Cowork toggle in Sep 2026 (TechCrunch, Yahoo). The press image still ships the toggle, so October 2026 users see two generations of the composer.
- Mode-naming churn: Code permission modes were renamed from "Ask permissions / Auto accept edits / Plan mode" to "Manual / Accept edits / Plan / Auto / Bypass permissions" and the "Summary" transcript mode was dropped (docs); Cowork uses a different set ("Ask / Auto / Skip"). Same concept, three vocabularies.
- Dark mode regression: GitHub issue #48158 (14 Apr 2026, marked critical) reports the Code tab's dark theme moved from layered warm grays to pure black with saturated blue user bubbles, "harsh" and "dated"; it broke the one-accent rule.
- Reliability and polish: reviewers report "buttons that do nothing, pages not properly connected" and pane layouts that "do not always persist across updates" (miraflow); a MacStories test cited ~50% task success; a hands-on review hit a Google Calendar connector that authenticated but was not recognized (eesel).
- Long-running work is under-visualized: Cowork shows a list subtitle and a spinner, but no elapsed time, progress fraction or ETA; Dispatch intentionally hides steps ("messages you the outcome ... rather than showing you every step"), which is calm but opaque when something stalls.
- No slim status bar or token/cost readout in Chat/Cowork (the Code tab has only a usage ring); Hermes/Paseo expose that at a glance.
- Typefaces are licensed (Copernicus, Styrene B) with no public web fonts, so any recreation must substitute (Tiempos/Cormorant + Inter), and the exact app dark tokens are unpublished.
